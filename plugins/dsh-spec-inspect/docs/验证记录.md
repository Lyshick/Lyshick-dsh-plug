## 4. HTTP 路由联调

启动 Host 后，在 `http://127.0.0.1:<port>` 上验证：

### 4.1 状态

```http
GET /spec-inspect/status
```

```json
{
  "ok": true,
  "value": {
    "indexUrl": "http://<index-host>/test.json",
    "settingsPath": "C:\\Users\\<user>\\.dsh\\spec-inspect.json",
    "version": "0.1.0",
    "hasIndexUrl": true
  }
}
```

### 4.2 保存索引源

```http
POST /spec-inspect/settings
Content-Type: application/json

{ "indexUrl": "http://<index-host>/test.json" }
```

返回 `ok: true`，文件写入 `~/.dsh/spec-inspect.json`。

### 4.3 读取索引

```http
GET /spec-inspect/index?refresh=1
```

返回：

```json
{
  "ok": true,
  "value": {
    "indexUrl": "http://<index-host>/test.json",
    "channels": [
      {
        "id": "web",
        "name": "Web 渠道",
        "docs": [
          {
            "id": "html-style",
            "title": "HTML 编写规范",
            "url": "http://<index-host>/default-skill.md",
            "type": "md"
          }
        ]
      }
    ],
    "warnings": [],
    "fetchedAt": "..."
  }
}
```

索引文档本身是 `web-check` 规范，级别定义为 P0-P3；插件不会因此硬造 P4/P5。

### 4.4 会话与文档错误分支

不存在的 session：

```json
{ "ok": false, "error": { "code": "no_session", "message": "未找到目标会话：请先打开一个会话再点击“开始检视”" } }
```

合法 session + 不存在的 docId：

```json
{ "ok": false, "error": { "code": "doc_not_found", "message": "索引中找不到文档「__missing__」" } }
```

第二条结果说明请求已经通过 `startInspection` 的 Agent 查找，只是没找到文档；**不会**往会话里发消息。用它可以在不触发真实检视的情况下验证 Agent 查找和索引读取。

## 5. Live Slot 与客户端模块验证

通过客户端 Slot 检查：

- `conversation.session.header.utilities` 的 occupants 中出现：

  ```json
  {
    "id": "spec-inspect-trigger",
    "order": 10,
    "active": true
  }
  ```

- `sidebar.right.pane.tab` 的 occupants 中出现：

  ```json
  {
    "key": "dsh-spec-inspect/picker",
    "active": true
  }
  ```

Host 侧 `clientModules` 检查最终结果：

- `clientPath('dsh-spec-inspect')` 返回 `plugins/dsh-spec-inspect/client.js` 的绝对路径；
- 客户端模块图 `entries` 中包含 `dsh-spec-inspect`。

> 调试过程中曾出现 `clientPath` 为 null、模块图缺失本插件的情况；原因是同名旧插件删除后，客户端扫描器仍保留负缓存。清理缓存后恢复正常。详见 [踩坑与排查.md](踩坑与排查.md) 第 1 节。

## 6. 未在本次验证中自动执行的部分

- **真实点击入口并打开 Tab**：需要人工点击右上角图标；Slot 已注册，Tab 类型注册代码与正文注册在同一 `apply` 中执行。
- **完整检视回合**：`/start` 成功会真的往当前会话发一条长提示词并跑一轮检视。本次只用“合法 session + 不存在的 docId”验证到 `doc_not_found`，避免在收尾时产生多余回合。
- **浏览器视觉走查**：未做截图/像素级走查；入口与页面均已按宿主主题 token 实现，建议安装后人工确认深浅色和窄宽度下的布局。
