## 0. 2026-10-26 客户端交互改版

本次改了三处客户端行为（`index.js` 未改动）：

1. 空会话入口：在 `conversation.hero.options` 补注册 `spec-inspect-hero-trigger`（仅空白会话渲染），组件用 `position: fixed` 对齐到 `[data-conversation-header-corner]` 左侧，视觉位置仍为右上角、侧边栏开关旁边；有内容后由 `conversation.session.header.utilities` 的入口接管；
2. 渠道 / 文档改为自绘下拉（`position: fixed` 菜单，避免右侧栏裁剪）；
3. 标题右侧新增刷新按钮，直接 `GET /index?refresh=1` 并保留当前选择。

验证结果：

- `node --check client.js` → exit 0；
- `node _selftest.mjs` → 6 checks passed（Host 纯函数未变）；
- 客户端热更新后 Slot 查询：
  - `conversation.hero.options` occupants 出现 `spec-inspect-hero-trigger`，`order: 10`，`active: true`；
  - `conversation.session.header.utilities` 的 `spec-inspect-trigger` 仍 `active: true`；
  - `sidebar.right.pane.tab` 的 `dsh-spec-inspect/picker` 仍 `active: true`；
- `GET /spec-inspect/status` → 200，返回当前索引源与设置路径；
- 客户端模块整体加载成功（`apply` 顺序执行到 hero 注册之后仍注册了 tab），没有加载期异常。

未在本次自动验证的部分：

- 下拉的展开 / 收起、上下翻转、外部点击关闭等交互；
- 刷新按钮点击后的 loading 与选择保留；
- 空会话页面的人工视觉确认（需要打开一个“已创建、未发消息”的会话）。

> 本地 link 安装时 Host 不需要重启；客户端改动刷新页面即可加载新 `client.js`（本次热更新已生效）。

## 0.1 2026-10-26 检视结果面板（定位 / 应用修复）

新增：

- Host：`GET /spec-inspect/report`（读取会话事件日志、解析 P 级报告）、`POST /spec-inspect/apply`（把一条修复建议发给会话 Agent）、`/start` 返回 `startSeq`；
- Client：picker 卡片下半部分的报告面板、按级别分组、展开详情、定位按钮、应用修复按钮、轮询与“重新读取结果”。

验证结果：

- `node --check index.js` / `client.js` → exit 0；
- `node _selftest.mjs` → **10 checks passed**（报告解析、非报告拒绝、修复指令、完整 UserMessage）；
- 真实会话报告读取（对 `session-bbb8ec2b-…`，即 `E:\HtmlDemo\20250425game`）：`GET /spec-inspect/report` 返回 `state: ready`，解析出
  - `P0` 0 条、`P1` 1 条、`P2` 3 条；
  - 字段完整：`path` / `line` / `endLine` / `issue` / `reason` / `basis` / `risk` / `fix`；
  - 位置 `js/game.js:124-140`、`js/game.js:65-70` 等均正确提取；
- `GET /report?sinceSeq=999999` → `pending`（轮询语义正确）；
- `POST /apply` 缺 `fix` → `{ ok:false, error:{ code:'no_fix' } }`，**不会**发消息；
- `/report` 返回的条目带 `applied` 标记；成功态在界面上显示为淡绿色勾标签“已修复”，记录写入设置文件 `applied` 字段（重启后仍保留）；
- **聊天用户气泡**：逐帧解压会话日志（`zstd` 多帧 NDJSON）后发现，插件发出的 `user/message` 事件只有 `content` + `source`，缺 `role` / `id`；正常注入消息都带 `role: "user"` 与 UUID `id`。`Agent.followup` 不补这两个字段，而 Chat 投影按 `event.data.id` 认领消息，导致 AI 虽然收到并执行，界面却不渲染用户消息。已改为发送完整 `UserMessage`（`userMessage()`，`/start` 与 `/apply` 共用）；待下一次点击「应用修复」时在聊天里确认用户气泡出现；
- 插件禁用/启用重载后路由生效；客户端 Slot `dsh-spec-inspect/picker` 仍 active，模块加载无异常。

未自动验证的部分：

- 真实点击“定位”后文件预览跳转与行高亮；
- 真实点击“应用修复建议”后 Agent 的修改回合；
- 检视进行中的自动轮询出现时机（需要跑一次完整检视）；
- 报告面板在窄宽度/深色下的视觉走查。

## 4. HTTP 路由联调

启动 Host 后，在 `http://127.0.0.1:<port>` 上验证：

### 4.1 状态

```http
GET /spec-inspect/status
```

```json
{
  "ok": true,
  "value": {
    "indexUrl": "http://<index-host>/test.json",
    "settingsPath": "C:\\Users\\<user>\\.dsh\\spec-inspect.json",
    "version": "0.1.0",
    "hasIndexUrl": true
  }
}
```

### 4.2 保存索引源

```http
POST /spec-inspect/settings
Content-Type: application/json

{ "indexUrl": "http://<index-host>/test.json" }
```

返回 `ok: true`，文件写入 `~/.dsh/spec-inspect.json`。

### 4.3 读取索引

```http
GET /spec-inspect/index?refresh=1
```

返回：

```json
{
  "ok": true,
  "value": {
    "indexUrl": "http://<index-host>/test.json",
    "channels": [
      {
        "id": "web",
        "name": "Web 渠道",
        "docs": [
          {
            "id": "html-style",
            "title": "HTML 编写规范",
            "url": "http://<index-host>/default-skill.md",
            "type": "md"
          }
        ]
      }
    ],
    "warnings": [],
    "fetchedAt": "..."
  }
}
```

索引文档本身是 `web-check` 规范，级别定义为 P0-P3；插件不会因此硬造 P4/P5。

### 4.4 会话与文档错误分支

不存在的 session：

```json
{ "ok": false, "error": { "code": "no_session", "message": "未找到目标会话：请先打开一个会话再点击“开始检视”" } }
```

合法 session + 不存在的 docId：

```json
{ "ok": false, "error": { "code": "doc_not_found", "message": "索引中找不到文档「__missing__」" } }
```

第二条结果说明请求已经通过 `startInspection` 的 Agent 查找，只是没找到文档；**不会**往会话里发消息。用它可以在不触发真实检视的情况下验证 Agent 查找和索引读取。
